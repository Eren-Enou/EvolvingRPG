# V0.4 C1 — meaningful evasion evidence

Implemented for Editor validation, 2026-11-04. This slice collects diagnostic evidence only. It grants no mastery, XP, knowledge reveals, talents, purchases or combat benefits. Existing PracticeTest remains the separate earlier practice experiment; C1 copies EnemyTest so its own scene has no HeavyPractice component.

## Create and launch the sandbox

Use the existing Unity **6000.6.7f1** Editor. No second instance is needed, and no scene is automatically opened or created when scripts import.

1. Let Unity import/compile the scripts. Save any scene edits you want to preserve.
2. Choose **Tools > EvolvingRPG > Create Evasion Evidence Sandbox**.
3. Open **Assets/Game/Scenes/EvasionEvidenceTest.unity** from the Project window.
4. Press **Play**, click the Game view, and approach the guarded opponent. Let its yellow windup start, then dodge early backward or laterally far enough to leave the strike.
5. Read the C1 panel's threat identity, dodge sequence, actual displacement, sample count, classification and explanation.

The builder requires an existing saved EnemyTest, creates an additive copy, saves only that new copy, restores the prior active scene and refuses to overwrite an existing EvasionEvidenceTest. If creation fails, it removes only the copy created by that invocation. Prior scenes and prefabs are not edited. The included scene was generated by this builder through Unity APIs.

No manual component wiring is needed after successful creation. Reusing the collector elsewhere requires explicit opponent references; the sandbox builder registers both existing opponents. Unknown/spawned enemies are outside this experiment's supported roster until registered.

## Controls and manual cases

Movement, Q/E strafing, Space jump, mouse look/zoom, LMB Light, RMB Heavy and Shift dodge retain their existing controls and parameters. There is no dodge invulnerability. R uses the existing encounter reset. F6 clears old combat diagnostics, not C1's deduplication state or bounded evidence history.

The fast opponent starts inactive to keep the first case inspectable. **F3** toggles it; press R first near the original central spawn if testing overlapping attacks, so both opponents can approach. F1 still toggles the old opponent detail panel. Use the compact view if panels overlap in a small Game view.

| Manual case | Expected diagnostic |
| --- | --- |
| Early dodge after commitment; original capsule threatened; actual path safely clear | Verified, if full sampling and normal strike/dodge completion are supported |
| Dodge in empty space | Rejected: no relevant threat |
| Dodge before the enemy commits | Rejected: cannot adopt that later strike |
| Enemy misses the starting position regardless of movement | Rejected: starting capsule not threatened |
| Dodge against a wall | No verification; obstructed travel or incoming contact explains the rejection |
| Incoming hit during the evidence interval | Rejected, even if dodge later completes |
| Interrupt/stagger the enemy before its active interval completes | Unverified interrupted strike |
| Reset actor or opponent during collection | Unverified reset; no old result becomes eligible again |
| Two committed threats against the actor | Unverified overlap |
| Low frame rate or missing samples | Unverified, not assumed success |

Starting a second action before the evidence finishes is unverified. Declining to counterattack is fine; C1 requires no Heavy after dodge. Wait for a fresh enemy commitment after toggling an opponent that was mid-attack, since its resumed old phase has no valid live evidence lifecycle.

## Implementation boundary

### Committed threats

`SandboxEnemy` exposes immutable `EnemyThreat` snapshots and local committed/finished events. Identity uses source object reference, intended target reference, encounter revision and strike sequence. Captured data includes committed facing, origin, range/arc and nominal active interval. A cached managed-reference hash stays stable if a Unity object is destroyed; these are not persistent IDs.

Normal active completion, poise interruption/defeat, reset, disable and target reset/change have explicit terminal receipts. The current pending threat is cleared before callbacks to prevent reentrant duplicate completion. `LastCommittedThreat` retains attribution for an old phase resumed after disabling, without pretending it completed a fresh evidence lifecycle. Enemy balance and original phase/timing values are unchanged. Old resumed phases are classified conservatively rather than changing how disabling the existing AI works.

Incoming `HitData` optionally carries the source receiver and threat identity. Existing constructors/callers remain supported. The player receives damage through the same vitality path; evidence does not absorb or alter it.

### Shared contact rules

`StrikeContactQuery` centralizes range, committed-facing arc and the existing default-layer, trigger-ignoring line-of-sight rule. Actual hit attempts preserve `CharacterController.ClosestPoint`; the stationary-position proxy translates the native controller query into the captured pose and feeds the same underlying contact/LOS rules. Unity query dimensions differ from the authored capsule; an ideal analytical capsule is reserved for the conservative safety enclosure. Physics queries do not move a collider or apply damage.

For supported poses, collection requires the native closest point to remain inside the authored enclosing capsule (0.015 m tolerance). Native translated queries preserve the actual hit boundary without moving or spawning colliders. Unsupported tilt, asymmetric horizontal scale, shape changes, vertical changes over 0.05 m, dynamic LOS blockers or source-origin drift over 0.02 m also refuse verification. Original hit behavior still works outside these evidence restrictions.

The captured geometry is used for the live strike query. Inspector edits to its range/arc affect later commitments; changing timing/geometry fields during collection invalidates evidence. This protects receipt consistency, not a new balance rule.

### Actual dodge observations

Only the player in the new scene receives `EvasionEvidence`. It subscribes to accepted/completed/interrupted action observations and vitality/reset receipts. Accepted direction, capsule, timing and action sequence are captured before travel. LateUpdate samples the actual post-motor capsule and `CollisionFlags.Sides`; the Starter Assets motor remains the only runtime movement integrator.

The result retains the dodge's actual end capsule, completion/interruption, displacement and traveled path, separately from the continuing evidence interval. The interval may outlast dodge recovery until the enemy finishes. Another accepted action invalidates attribution. Any incoming contact before finalization rejects, including a different attacker's contact.

### Conservative trajectory proof

The original capsule must be contactable at an observed active sample, including LOS. Its proxy is mathematical only: no collider is spawned at the old position.

Actual safety requires more than safe endpoints. For each supported frame overlapping the active interval, the previous capsule is expanded by the configured **maximum supported speed × sample gap**, plus a 0.02 m source/error margin. This encloses supported motor travel without assuming a straight line between endpoints. The enclosure must be wholly outside range or arc. LOS is deliberately ignored for this safety proof, so a wall protecting the actor cannot masquerade as a geometric evasion. If the enclosure could contact, the result is **Unverified**, even when no hit was applied.

Defaults support gaps up to **0.025 s** and movement speed up to **16 m/s**. These are evidence bounds, not movement changes. Observed motion beyond the bound, a late start after active begins, an early/incomplete threat completion, a pose mismatch, or absent coverage refuses verification. Approximately 30 FPS or 15 FPS is intentionally unsupported by the default proof. Do not raise the gap just to get more green results; review the proof and motion assumptions first.

This relies on the known single-motor sandbox movement and registered enemies. Arbitrary external teleports between samples, moving platforms, unregistered attackers and general moving-strike geometry are not supported. Player/reset and known source lifecycle changes are observed explicitly. It is a conservative supported-system proof, not a general continuous-physics replay.

### Result interpretation and bounds

`EvasionAttempt` is a deterministic reducer; `EvasionResult` is an immutable diagnostic receipt. Verified means **a committed strike was avoided during a completed dodge while the stationary starting-position proxy was threatened**. It does not prove perfect timing, that walking could not have worked, or that dodge was the only causal factor.

Side collision or less than 80% of intended travel rejects obstruction. This deliberately rejects some useful partial/late evasions. A second threat, unsupported frame or possible swept contact is unverified rather than a negative skill judgment. A valid result requires both full dodge recovery and normal active-interval completion.

One candidate is pending per actor. Replayed accepted sequences and terminal events do not replace it. A threat/actor emits at most one result; used keys survive player-only reset and are pruned when their source revision changes. History is capped at 16 receipts, used threats at 64, and an attempt at 512 samples/five seconds. Capacity exhaustion fails closed. Clearing diagnostics does not reopen old evidence.

## Automated checks prepared for the Editor

With scenes saved and Play mode stopped, choose **Tools > EvolvingRPG > Run Evasion Evidence Checks**. This explicitly creates the sandbox if missing, opens it, enters Play mode and exits after the suite. Do not run it while making interactive edits. It writes **Logs/EvasionEvidenceChecks.txt**.

Prepared cases cover:

- Deterministic threatened-start verification, no threat, pre-commit dodge, harmless miss, obstruction, incoming contact, interrupted dodge and player reset.
- Interrupted/reset enemy, overlapping threats, low/incomplete sampling, unsupported geometry, duplicate processing and revision identity.
- Real physics contact versus proxy geometry, wall obstruction, dynamic blocker ambiguity and query damage isolation.
- Actual enemy commitment, once-only damage, incoming identity, normal completion, poise interruption and resets.
- Collector receipt/duplicate handling and a second real opponent commitment. These isolated event fixtures are distinct from the native movement cases.
- Normal-frame Starter Assets dodge at 60 Hz simulation, real wall-clipped displacement, unchanged facing/distance, and unverified 15 Hz sampling. The fixture settles bodies before capturing source geometry and restores simulation settings afterward.

For regressions, run the existing menus individually after C1:

1. **Run Combat Play Mode Checks** — existing attack, camera, jump, strafe and interruption cases.
2. **Run Technique Play Mode Checks** — existing Heavy/motor behavior.
3. **Run Enemy Play Mode Checks** — existing enemy/damage/guard behavior.
4. **Run Practice Play Mode Checks** — previous session practice/refinement behavior.
5. **Run Attack Snapshot Checks** — committed values and miss feedback (use the existing menu title shown by the project).

Do not treat a previously generated report as a pass for this revision. Read the new report and Console after actually running each requested suite. Functional passes still would not validate feel.
