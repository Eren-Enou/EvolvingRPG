# First complete slice contract

Proposed acceptance contract for future development. This document compresses the larger design into demonstrations small enough to build and review. It does not advance the current milestone or authorize running Unity during the present documentation assignment.

## Demonstration A — a complete character-development loop

Use the existing Warrior fundamentals and a meaningful opponent. Provide two behaviorally distinct Heavy choices, one familiarity track, one reproducible contextual discovery, deliberate investment and a minimal versioned save. This is the talent charter's first complete loop at small scale.

The demonstration should let a player:

1. Start a genuinely fresh Warrior with ordinary Light, Heavy, Dodge and movement.
2. Fight and see understandable qualifying Heavy practice, including an explicit explanation for rejected outcomes.
3. Inspect the two visible Heavy developments, preview their behavior and deliberately select one with a controlled test resource.
4. Experience a clue and reveal under the chosen authored rule. Reveal alone changes no active behavior.
5. Deliberately learn/configure the revealed interaction if eligible and able to pay its stated cost.
6. Save, exit the test session and reload to the same legal character state, without restoring an active dodge/retaliation opportunity.
7. Create a second fresh Warrior and choose a different development. Account knowledge, if represented, grants no inherited power or prerequisites.

Use a labeled fixture to grant controlled resources before mission rewards exist. It must award a given fixture grant at most once per character. Provide enough test resources to demonstrate both the initial choice and the later optional investment; do not reveal an option that can never be selected in the only available test. This is not a selected release economy.

The UI can be a small development panel and journal. A large map is unnecessary, but knowledge, eligibility, ownership and active configuration must remain honest.

### Resolve these gaps before calling A complete

- C2 currently models a defensive investment with a session fixture. Do not sell an empty Dodge node solely to gate discovery. Either select an independently useful supporting development, or explicitly revise the authored discovery rule to use actual defensive practice plus the real Momentum investment. Record the change; do not silently reinterpret the fixture as a learned talent.
- The first choice's familiarity prerequisite must not exclude competent opening play solely because an enemy never attacked. Review that gate before presenting a polished opening.
- The retaliation effect needs target-generation success and acceptance-linked consumption. A raw any-target contact count is insufficient.
- Saving retained mastery requires a coherent replay/budget policy. Session-only PracticeTest resets cannot become production persistence by serializing its Points property alone.

## Demonstration B — one game-shaped expedition

Connect A's validated state to a compact hub, a single authored mission site and one controlled milestone reward. Use existing enemy roles and no required equipment economy. Let the player accept, deploy, complete or fail, return, inspect the report, make a development decision and deploy again.

Mission settlement and practice-budget retention must agree across retry, checkpoint, application close and repeated debrief. A visible safe save boundary is sufficient; mid-sword-swing persistence is unnecessary for this slice.

The mission can use placeholder art. It still needs readable anticipation/contact/recovery, camera-safe geometry, a comprehensible objective and a clear return route. The narrative wrapper may remain provisional.

## Demonstration C — the loop develops rather than repeats

After B works, compare a second authored contract on familiar geometry, two equal-resource character paths and one adjacent support. Add one announced regional patrol change or visible hub consequence. Do not add all possible expansions at once.

Ask whether the developed character approaches the site differently, whether the other path remains viable, and whether the world change offers another question rather than negating the specialty. If the answer is only bigger damage numbers or a longer health bar, revise the encounter/application before expanding the region.

## Small content ceiling for this contract

Candidate envelope: one Warrior foundation, one supported melee weapon family, two visible Heavy alternatives, one discovery/effect, one track, one tiny hub, one mission site, existing guarded/fast roles, one saved character model and two test character records. A guardian, second region, procedural generation, extensive equipment and a full archive service are outside this envelope.

This is a scope tool, not a permanent ceiling for the game. New content should enter because a demonstration needs another decision, not because a placeholder menu has empty slots.

## Exit evidence

Record separately: source/definition changes, technical validation, player feedback and unresolved design questions. A clean compile cannot establish that an evolution is fun. A satisfying single fight cannot establish save integrity, long-term specialization or reward resistance to replay.

The player should be able to explain what their character learned, what they deliberately chose, how it changed the next fight, and why a new possibility appeared. The game should preserve that character without turning their history into automatic access to every peak path.

Implementation and all demonstrations remain future work. No Unity session, tests or gameplay validation occurred for this contract.
