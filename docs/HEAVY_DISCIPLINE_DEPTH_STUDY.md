# Worked study: depth within the Heavy discipline

Future investigation, not an implementation or test report. Use with [DEPTH_FIRST_DESIGN.md](DEPTH_FIRST_DESIGN.md), [the timing worksheets](COMBAT_TIMING_WORKSHEETS.md) and [the narrow discovery specification](CONTEXTUAL_DISCOVERY_EXPERIMENT.md). Unity must remain untouched during this design assignment.

## The question

Can one invested Heavy discipline keep producing better-informed and genuinely different decisions as a character develops, while preserving understandable controls and a recognizable liability?

The primary candidate is Momentum: committed travel into an opening, lower poise impact than disruption, and extra exposure when it misses. Keep Baseline Heavy and Breaker as separate comparisons. The test Warrior uses its selected Heavy plus ordinary Light, dodge, jumping, walking and strafing; number-key debug switching between all Heavy variants is not a model for normal character ownership.

We are testing a lineage, not filling an entire Warrior tree. A satisfying result can use the same RMB repeatedly if starting position, timing, facing, opportunity choice and ending risk are meaningful. Different button counts are not the measure of depth.

## Fixed investigation envelope

Keep the current weapon family, authored attack values, camera controls, stamina settings and two opponent roles. Use open space and existing obstruction cases. Add no item effects, extra defensive system, magic, new currency or randomized talent content.

Do not combine the current recovery trial with a new retaliation effect on the first comparison. Start each with its own disabled reference. If both are individually retained, their combination is a later selected case, not an assumed entitlement.

Use a single opponent first. Mixed threats come later using the roles already implemented. No new guardian is needed to answer this study's initial question.

## The learning ladder

The rows describe distinct questions, not automatic level rewards.

| Step | Character/system change | Deeper question | What would falsify the idea? |
| --- | --- | --- | --- |
| H0: understand the ordinary commitment | None | When can a Heavy connect and when can control return safely? | The player cannot read whether a miss was distance, facing, wall or interruption |
| H1: invest in advancing technique | Selected authored Momentum profile | Where should I start, face and finish a committed approach? | It is strictly preferable in every relevant case, or travel feels arbitrary |
| H2: test familiarity | One bounded base-recovery refinement only | Does modest refinement make a known application more reliable without erasing its decision? | Benefit is imperceptible, or automatically defeats all intended recovery pressure |
| H3: establish defensive relationship | Verified evasion evidence and knowledge, no effect | What actually created this opening, and can I recognize when it exists? | Nearby harmless dodges count or the clue requires artificial spam |
| H4: choose a return application | One optional learned/trial retaliation application | Should this opening become a longer drive, a short action, repositioning or retreat? | Correct play always means consuming the opportunity immediately |
| H5: integrate the discipline | No new mechanic initially | Can I use the same application safely when the next threat, line or starting distance changes? | More nodes are needed merely to keep the original technique viable |
| H6: express the developed method | One matching presentation pass | Can I read my own commitment and recognize the developed style? | Animation implies steering/protection/timing the mechanics do not supply |
| H7: select the next unresolved question | At most one candidate extension, only after evidence | What specific choice remains valuable but poorly expressible? | The proposed answer only adds power or repairs a baseline defect |

Familiarity and discovery need not occur in this exact player chronology. The order isolates the sources of change during development. No progression threshold is inferred from this table.

## H0/H1: one action, several legitimate judgments

Use the same selected technique and observe these cases before inventing another talent:

| Situation | Decision to investigate | What the same Heavy must still respect |
| --- | --- | --- |
| Target just beyond ordinary contact | Approach first or spend committed travel now | Initial facing, real reach, collision and enemy commitment |
| Target already close | Whether advancement improves the ending position or exposes it | Enemy body collision, another threat and recovery |
| Target in a long recovery | How much time remains for contact and the whole player action | Next possible attack, not merely current green/opening feedback |
| Target in a short recovery | Light, movement, a risky trade or Heavy | No guaranteed counter merely because the prior attack missed |
| Target frontal and guarded | Build poise pressure, move around it or wait for a different opportunity | Momentum does not gain Breaker's poise through familiarity by default |
| Clear target with a wall near the travel line | Commit, reposition or avoid the approach | Travel can shorten; no geometry bypass |
| Same target, another visible threat preparing | Take the opening or preserve safety | A valid hit can still be an unsafe decision |

These are hypotheses for future sessions, not prescribed solutions. The player may find a good approach we did not predict. Do not judge depth solely by whether they choose the designer's preferred button.

## H2: a refinement with an explicit limit

The current practice trial changes Momentum base recovery from 0.45 to 0.414 seconds while preserving its miss addition. That is a 0.036-second saving. It may be hard to perceive broadly while affecting a narrow boundary. No player evidence for this effect is assumed here.

Compare the same approach with refinement off/on. Record whether it changes a real ability to return to control or simply changes a number. If it is too subtle, alternatives include a clearer control refinement or a different bounded field; automatically increasing the percentage is not the only answer.

Do not make this refinement a gate that every future application must stack with. Character mastery is not required to make basic action timing honest. The player should be able to understand a discipline before being told that many hours of refinement fix its responsiveness.

## H3: discovery concerns relationships

A verified dodge and later completed Momentum hit can reveal that evasive movement and advancing commitment have a coherent relationship. The detailed C1/C2 receipt rules remain necessary. An enemy miss alone is insufficient, and an ordinary dodge does not need a bonus to be useful.

The temporary defensive-investment fixture is unresolved content. Before real purchasing, either author an independently worthwhile defensive development or explicitly change the rule to use actual defensive practice plus the real Momentum investment. An empty prerequisite makes the tree longer without making the discipline deeper.

Keep a clue intelligible without demanding one exact scripted sequence every encounter. A character may continue ordinary familiarity while pursuing the clue slowly. Missing a contextual opportunity is not a failure to play the discipline correctly.

## H4: the return application must remain optional in use

The current proposal grants one longer committed approach after finalized evasion evidence, with target-specific miss exposure. Its core question is "is this a good line to return through?" The linked opponent identifies the relevant exchange, not an automatic aim target.

The attack still uses the player's intended facing. Q/E strafing and a lateral dodge do not auto-turn the character into the enemy. Mouse look remains camera control. Extra travel does not excuse an incorrectly faced strike.

Before implementation, choose and document the input-intent policy described in [the depth design](DEPTH_FIRST_DESIGN.md). Conditional movement needs a reliable cue and a way the player can anticipate the result. The current trial concept has not settled whether Heavy always takes the armed form, directional intent opts in, or handling is chosen at a safe location.

The opportunity expires if unused. Do not punish the player with a negative status, loss of unrelated practice or a "failed combo" message for choosing to leave it. Its benefit is access to a particular application; its cost occurs when that application is accepted and committed.

## H5: six contextual probes using the same vocabulary

These probes change one important relationship at a time. A future fixture must actually establish the stated eligible evidence, not merely flip a ready flag and call the full chain validated.

### Probe A — room to return

Use a single guarded opponent, an unobstructed line and a verified evasion. The target is still within the actual reachable envelope after the dodge. The player can choose an immediate advancing return or another response.

Ask whether the extra approach enables a deliberate contact from a distance the ordinary version would not use as well. Check full recovery, ending position and the next enemy threat. A successful contact alone does not prove the application worthwhile.

### Probe B — little room to advance

Use the same role but start closer or end the dodge on a different side. Keep a valid evidence chain. Extra forward travel may have little value or worsen exposure, even if a collision prevents literal overshoot.

Ask whether the player can anticipate that result and choose Light, movement or waiting. Do not force a failed Heavy to teach the drawback. If conditional advancement makes ordinary intent unreliable, inspect the control policy before calling the mechanic challenging.

### Probe C — a short enemy reset

Use the fast opponent and the paper timing concerns already identified. A return that hits can still leave the player committed during a possible next strike. Prior poise, facing and path can change the result.

Ask whether the player recognizes when the application is a risky trade. Do not promise that every verified evasion guarantees a safe Heavy. If a viable use never exists, revise the application or context rather than demanding an invisible mastery threshold.

### Probe D — clipped travel

Create valid evasion in unobstructed geometry, followed by a return line whose movement can be clipped by a nearby wall or body. The wall must not be the original reason the enemy strike missed; that would invalidate the evasion evidence.

Ask whether ending position and contact match the visible space. Reduced travel is ordinary collision, not a bonus or proof of restraint. A geometry failure should remain explainable by the existing miss feedback.

### Probe E — another threat after the advantage

Add the existing second role only after the single-threat case works. Its new threat begins after the defensive receipt is finalized, so a previously valid opportunity can become tactically unsafe. Any incoming hit during C1's evidence interval still follows the conservative rejection rule.

Ask whether the player can decline an otherwise valid return and preserve a useful position. Success is not a maximum use rate for the effect. If the second role is offscreen or unreadable, fix composition/camera/presentation before interpreting the result as poor judgment.

### Probe F — the opportunity is no longer the same exchange

Reset, defeat or remove the linked target before effect acceptance, or let the window expire. Ordinary legal Momentum can remain available under the documented fallback; the invalid contextual benefit does not apply.

Ask whether the cue and explanation make the ordinary behavior predictable. A reset object with the same reference is a different target generation. Diagnostics clearing cannot revive the opportunity.

## The disruption reference asks a different question

Run the same broad situations with a separately invested Breaker Warrior. Do not give that character Momentum mid-fight to avoid an inconvenient situation. Its fundamentals and preparation should supply a viable way to solve the encounter.

What may change: a frontal guard becomes a reliable disruption opportunity, while closing and repositioning remain more deliberate. A successful break does not require an automatically enhanced follow-up. Sometimes the meaningful result is time to move or deal with another threat.

The current proposed Light-poise follow-through is a poor next-depth assumption because the target may already be staggered and little useful break time remains after the Heavy completes. Keep it dormant until a real unresolved follow-up question exists. The name "advanced follow-through" does not establish value.

## Paper check: can disruption collapse into a repeat loop?

An idealized fresh Breaker impact has roughly 0.18 seconds of active time and 0.85 seconds of recovery left. With a 0.65-second next windup, another contact can occur about 1.68 seconds after the prior impact.

Source inspection shows an important extra stage: SandboxEnemy enters Recovery after Staggered ends. For the guarded opponent, a 1.2-second stagger followed by 1.15-second recovery and a new 0.85-second windup gives about 3.20 seconds before the next possible active contact, plus frame/approach effects. A simplified model that jumped directly from stagger to windup would understate that interval.

CombatVitality applies no poise while Staggered, but the next ideal Breaker contact at 1.68 seconds is after the 1.2-second stagger and during post-stagger recovery. If it applies its full 60 poise against a fresh 60 threshold, it can break again before another enemy strike. Repeated contact may therefore sustain a safe loop until defeat under these assumptions. This is a source-informed paper concern, not an observed exploit or a claim about actual input/frame behavior.

Current stamina is intentionally permissive, so do not count resource starvation as the assumed cure. Do not change it during this assignment. Verify actual phases, poise reset, guard availability, input timing and collision in future testing before changing balance.

A disruption specialist being strong against one guarded opponent can be desirable. The question is whether it is an earned, readable strength with meaningful decisions elsewhere, or whether every later development simply amplifies an already automatic answer. Use the existing fast/mixed cases before inventing immunity enemies or a new stagger subsystem.

There is also an incentive to inspect: HeavyPractice consumes one credit budget per committed enemy strike. Further recovery breaks without a new strike do not provide another award, whereas waiting for a new commitment can reopen eligibility. Guarded contacts reduce HP damage, so pursuing repeat guard breaks may prolong the fight relative to striking exposed recovery. This does not establish an actual farming rate, but it explains why practice policy and encounter resolution must be evaluated together before durable progression.

## A specialist can choose the lighter finishing action

Consider a hypothetical non-staggered guarded target with 48 of its 60-poise threshold already accumulated, within both Light and Heavy reach. Its current windup has 0.30 seconds left. Assume an applied hit would not be blocked by geometry and prior accumulation has not decayed.

The existing Light begins contact after 0.12 seconds and supplies up to the remaining 12 poise. It can break the target before that ideal strike boundary. Breaker begins contact after 0.65 seconds, later than the boundary, even though its authored poise is much larger. A correctly selected Light can therefore serve the disruption goal better in this state.

This is arithmetic over a hypothetical state, not a measured response guarantee. Actual positions, input frames, movement and contact still matter. The useful relationship is that threshold remainder and time available can change the right commitment without requiring another talent or a new enemy.

CombatVitality clamps applied poise to the target's remaining threshold and applies zero while it is already staggered. A future progress rule based only on raw authored poise or total applied magnitude would miss part of this judgment. Conversely, current HeavyPractice deliberately gives no Heavy credit to Light; that is not itself an error. It is a reminder that the progression economy must not pressure a player to make every encounter decision with one button just to develop a specialty.

Do not solve this by silently granting Heavy XP for every Light on a Breaker character. Familiarity should describe what was practiced. Broader character history can record the real source action, build context and break outcome if an authored discovery needs them later. Interpretation remains explicit; the system does not infer a secret intention from the character's label.

The depth lesson is that specialization can organize the player's goals while fundamentals remain useful. A disruption specialist who chooses a quick finishing contact is still expressing judgment within that identity.

## Pressure already contains a stopping decision

The existing Light has a 0.12-second windup, 0.10-second active interval and 0.22-second recovery: 0.44 seconds total. Under an ideal simultaneous start against the guarded opponent's 0.85-second windup, one Light completes with time to begin another response; two sequential Lights finish around 0.88 seconds, after the enemy's first possible active start.

Two fresh Light contacts contribute at most 24 poise against that opponent's 60 threshold, so they do not automatically interrupt it. The actor may move during Light, actual starting distance matters, and ordinary incoming damage need not stagger the player. The result can be avoidance, a deliberate trade or a poor commitment. No runtime result is implied.

This already asks whether to stop after one short action, continue, move or accept risk. A future pressure development should enrich that question, rather than pay a bonus for always pressing the second and third Light. Investigate the existing decision before introducing C06 Pressing Rhythm.

## Compare the right axes

| Comparison | What it can tell us | What it cannot establish |
| --- | --- | --- |
| Same selected Momentum, effect off versus on | Whether the added application changes a decision | Overall balance between mature disciplines |
| Base Momentum versus base Breaker at comparable investment | Whether the initial technique profiles differ meaningfully | Whether one has a complete long-term lineage |
| Same character/configuration across a changed visible context | Whether judgment transfers and conditions matter | Character growth if no character mechanic changed |
| Fresh versus developed character with the same human player | Which effects belong to the character rather than human learning | New-player accessibility by itself |
| Two mature paths with matched resources and authored depth, later | Specialization tradeoffs and identity | Infinite progression balance or every future content interaction |

The current design does not give Breaker an equally developed contextual lineage. Do not compare advanced Momentum against an initial Breaker profile and declare the whole specialization superior. Complete one proof first, then decide whether another lineage merits the same treatment.

## Further depth: select the missing expression, not another roster

Only promote a successor application after H5 identifies a repeated, understandable problem that fundamentals cannot express adequately. Use this decision table:

| Observed need, if established later | First response | Possible later extension | What not to do |
| --- | --- | --- | --- |
| Player cannot predict when conditional travel applies | Improve intent policy/cue or redesign the condition | None required initially | Sell a talent that makes the interface truthful |
| Correctly faced travel is mechanically inconsistent | Fix movement/contact sampling at the baseline | None required for progression | Call a bug a discipline weakness |
| Long approach is useful but a shorter committed form creates a genuine alternative | Trial one replacement handling policy | A selected short-return application with an explicit cost | Stack automatic distance correction onto every Heavy |
| A moving target produces a deliberate preparation decision that current facing cannot express | Confirm it is a worthwhile control question | One bounded early-windup turn profile with a retained arc/commitment tradeoff | Add full tracking, turn correction and miss cancellation together |
| Guard break leaves a valuable escape decision | First use ordinary move/dodge when control returns | One recovery-positioning support with a real cost | Remove the planted discipline's entire commitment |
| The player simply wants more damage | Inspect encounter pacing and reward meaning | Possibly a bounded refinement if justified | Add a new named evolution without another decision |

Short-return and bounded-turn are counterfactual options, not two scheduled next talents. They would replace or separately compare handling before any combination is supported. Depth does not require making every candidate available.

## Two characters within one discipline, eventually

After an accepted application and a genuine successor decision exist, two Momentum-focused Warriors could emphasize different ways of using the same commitment. One might invest in extended return through an opening; another in a more constrained, deliberate handling form. They would share a discipline while valuing different starting positions and windows.

This requires real behaviorally distinct authored forms and opportunity costs. It cannot be demonstrated by renaming two recovery percentages. Neither form should automatically inherit all of the other's strongest control benefits, and neither gains Breaker's peak disruption solely by accumulating more general mastery.

The initial proof does not need both. First show that one lineage has an interesting next decision. The long-term tree can grow along retained questions rather than require a predetermined number of leaves at every depth.

## Keep supporting fundamentals alive

Light can fit a shorter opening or contribute poise without starting a longer approach. Walking can choose range and restore a line. Q/E can maintain facing while adjusting position. Dodge can avoid a threat without obligating a counter. Jump remains available without becoming a required progression sequence.

A Heavy-focused character does not need new talent nodes on every supporting action for these to be meaningful. When a support development is proposed, compare it to simply using the existing fundamental better. The character's main identity should remain visible after the support is added.

If Light is used only as compulsory setup for Heavy, inspect that incentive. If walking is never useful because all positioning is solved by automatic advance, inspect travel/control. Do not add separate Light and walking mastery trees to cover the failure.

## Evidence to record later

For selected exchanges, retain the accepted action and committed parameters, relevant threat/opportunity key, starting/ending state, actual contacts, interruption and return-to-control time. Use bounded diagnostics and a few clearly labeled captures. No analytics service or raw lifetime input log is needed.

Record player explanations separately from authoritative facts. "The player chose to preserve an escape route" is an interview/observation note; "the actor ended outside strike range" is a geometric fact. Neither implies the other automatically.

Compare the same player with a fresh versus developed character, and the same developed configuration in different visible contexts. Alternate order where practical. Familiarity with the test itself can improve results even when no character mechanic changed.

Useful signals include:

- The player predicts when the application helps and when it does not.
- A context change alters timing, route, facing, follow-up or decision to decline.
- The development enables a recognizable application beyond ordinary behavior.
- The player can identify a remaining limitation without calling the controls unreliable.
- Fundamentals still provide credible alternatives.
- Failure has an explainable consequence rather than an unseen exception.

Do not set a target percentage of opportunity consumption or talent-node use. Those numbers can reward shallow compliance. A player choosing the same Heavy in several contexts can still be making different meaningful commitments.

## Distinguish failure types

| Result | Interpretation to investigate | Next action |
| --- | --- | --- |
| No qualifying evidence despite intended valid play | Evidence or sampling defect, or unsupported case | Fix/clarify C1; do not increase combat reward |
| Opportunity unclear | Presentation/intent problem | Improve cue/control contract |
| Effect never tactically useful | Application/window problem | Revise or discard this effect while retaining useful evidence |
| Effect always best | Dominance, missing cost or weak context comparison | Inspect the full action and alternatives |
| Player improves equally with effect off | Human learning or broader practice | Do not credit the character mechanic without evidence |
| Both techniques solve everything identically | Insufficient role distinction or test context | Revisit existing profile/encounter questions before expanding |
| Specialist has no viable response to common threat | Foundational viability problem | Restore counterplay; do not hide it behind another mandatory branch |

## Stop and promotion gates

Stop new content if basic timing/geometry is unreliable, defensive evidence cannot explain itself, or conditional movement lacks a comprehensible intent policy. Do not spend the next development on more nodes while these remain unresolved.

Promote one further application only when a specific missing decision is repeatedly visible, the existing action remains useful, the proposed extension has a concrete drawback, and the player can explain what they would do differently. List the new implementation/presentation cost before selection.

The broader hub/save loop remains necessary to demonstrate character ownership and history. It should connect the accepted lineage rather than introduce multiple untested combat branches at once. [The experiment backlog](DEVELOPMENT_EXPERIMENT_BACKLOG.md) is refined by these gates, not expanded into a parallel feature schedule.

No playtest observations, pass/fail rates or player preferences have been collected for this study. All cases remain future work, and no Unity, runtime code, scene, prefab or stamina change is part of this document.
