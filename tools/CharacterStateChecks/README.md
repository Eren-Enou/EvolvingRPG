# Offline character-state checks

Run from the repository root, without opening or controlling Unity:

```powershell
$env:DOTNET_CLI_TELEMETRY_OPTOUT='1'
$env:DOTNET_SKIP_FIRST_TIME_EXPERIENCE='1'
$env:DOTNET_NOLOGO='1'
$env:DOTNET_CLI_HOME=Join-Path (Get-Location) 'Logs/OfflineCharacterState/dotnet-home'
dotnet run --project tools/CharacterStateChecks/CharacterStateChecks.csproj --configuration Release --no-launch-profile
```

Requires an installed .NET SDK and .NET 6 targeting/runtime packs. Verified locally with SDK 6.0.301 / runtime 6.0.6. No dependencies were installed. NuGet.Config clears package feeds; there are no PackageReferences. A machine lacking the targeting pack will need that prerequisite separately. Exit 0 means every case passed; exit 1 reports failures. No automatic execution on Unity import or Editor startup.

## Actual production subset

The project links these repository files directly, with no copied rules or Unity stubs:

- Assets/Game/Progression/CharacterDevelopmentState.cs
- Assets/Game/Progression/CharacterSaveData.cs
- Assets/Game/Progression/DevelopmentPurchasePreview.cs
- Assets/Game/Progression/HeavyExperienceCatalog.cs
- Assets/Game/Combat/DiscoveryKnowledge.cs
- Assets/Game/Expeditions/ExpeditionAttempt.cs

Program.cs is the test runner, not a replacement implementation. It checks fresh identity, empty-ID ownership, deliberate choices versus knowledge/activation, identity-bound/stale/default/replayed previews, history validation/deduplication, schema-1 migration, illegal DTO rejection, protected unknown-content fallback, snapshot isolation and portable DTO JSON roundtrip. Thirty seeded command traces of 100 steps check balances, history bounds, legal activation and restoration after every command. Assertions are repeated invariants, not 9,082 independent scenarios. Seed: 71051. Fresh GUIDs are intentionally generated by production code.

The JSON case uses System.Text.Json with IncludeFields. It does **not** test Unity JsonUtility, byte compatibility, the on-disk store, backup replacement, damaged-file recovery or future-save overwrite protection. All fixtures are in-memory; the harness never reads personal saves. Compiler/runtime caches and build outputs are ignored.

## Explicit exclusions

This is a .NET 6 compilation and test of six pure source files, **not a Unity project compilation**. Unity 6000.6.7f1 uses its own assemblies, runtime, lifecycle and serialization. No MonoBehaviour, UnityEditor, Input System, physics, frame timing, scene or prefab is included. In particular CharacterSaveStore, OwnedCharacter, DevelopmentPanel, experience receipt collection and all Editor checks are excluded. No Unity assemblies or substitute Unity APIs are referenced.

The transient preview and mission attempt are not serialized. Save schema 3 adds initial fixture funding and the first relay milestone; schemas 1/2 migrate in memory preserving one fixture point without inventing mission completion. Additional mission cases cover identity/terminal gates, stale and duplicate callbacks, failure/abandon/repeat/priority policy and equal-funded independent Breaker/Momentum characters. Current result: 11 cases, 9,111 assertions. Counts are repeated invariants, not independent gameplay scenarios.

Before accepting the branch as Unity-integrated, manually compile in the existing Editor and run Tools > EvolvingRPG > Run Extended Regression Checks from one saved, stopped scene. Fourteen stages now include the relay native suite. Follow docs/CONTINUOUS_DEVELOPMENT_REPORT.md for new scene setup and pending gates. Neither a green offline run nor older Unity results establishes these gates or gameplay feel.

`./tools/CompileUnitySources.ps1` additionally compiles current Game sources against the installed Unity compiler and cached real reference graph, writing only ignored Logs/SourceCompile outputs. It never launches Unity or injects assemblies into the Editor. It requires an imported project/cache and cannot verify graph freshness, asset import, serialization, physics, lifecycle or player builds.
